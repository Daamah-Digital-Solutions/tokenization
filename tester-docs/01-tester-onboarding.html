1. What Capimax does

Capimax is a real-estate tokenization platform. Property owners list real estate; each listing is split into a fixed number of digital tokens (ERC-1155); investors buy tokens through the platform; each token represents a fractional ownership stake.

The platform handles four major flows:

  1. Listing & approval — property owner enters the property; admin reviews and approves.
  2. Tokenization — the property is deployed as a smart contract on the blockchain; tokens become buyable.
  3. Investment — investor pays via card, bank transfer, or crypto; tokens are minted to their wallet on the chain.
  4. Returns — depending on the property type, investors either receive rental income distributions or hold tokens that appreciate as construction completes.

A secondary marketplace lets investors trade tokens with each other without going through the property owner.

2. The two property models

Capimax supports two distinct property categories. Each one has its own investment and ownership flow. Both are in scope for this testing round.

FeatureReady PropertyUnder Construction
Category code ready_property under_construction
Investor payment Single upfront amount Upfront OR installments (owner enables)
Token minting Immediate, direct to wallet Upfront: immediate. Installment: tokens escrow on contract; released as each installment is paid
Returns Rental income distributions Value appreciation through completion + potential later rental
Required owner fields monthly_rental_income, rental_distribution_frequency expected_completion_date, construction_progress, supports_installments, installment_period_months
Construction milestone tracking N/A Owner adds milestones; investors see progress

Critical to test

Make sure the platform behaves differently for each model. A ready property should never show construction-milestone fields. An under-construction property should never auto-trigger rental income. If you see the wrong category-specific UI, that's a bug.

6. Crypto wallet for token operations

Token minting and trading happen on a blockchain. Each investor needs a wallet address. We use BSC Testnet, which is free and isolated from real money.

Option A — use the platform-provided wallet

For most flows, the platform uses a shared test wallet so you don't need to install anything. The investor account you're logged in as is automatically associated with this wallet when you place your first investment. You'll see real token balances against this address.

Option B — bring your own wallet (MetaMask)

If you want to verify token balances independently, install MetaMask and add BSC Testnet. See section 7. BSC Testnet setup below.

7. BSC Testnet setup

Skip this section unless you want to verify token balances in your own wallet. You can complete every test without it — we'll always provide BSCScan links.

Adding BSC Testnet to MetaMask

  1. Open MetaMask

    Install from metamask.io if you don't have it.

  2. Click the network dropdown at the top → "Add network" → "Add a network manually"

  3. Paste these values:

    Network nameBNB Smart Chain Testnet
    RPC URLhttps://data-seed-prebsc-1-s1.binance.org:8545
    Chain ID97
    SymboltBNB
    Block explorerhttps://testnet.bscscan.com

  4. Save and switch to the new network

  5. (Optional) Get test BNB from the BSC faucet

    You only need test BNB if you intend to pay gas yourself. For platform-mediated investments, the platform pays gas.

Token visibility

Property tokens are ERC-1155 with property-specific token IDs. MetaMask doesn't show ERC-1155 balances natively, but you can verify them on BSCScan at any time using the property contract address and token ID (each property's clone uses tokenId = 0). See on-chain verification.

8. Your first login

  1. Open the frontend URL in a browser

    Local: http://localhost:5173

  2. Click Sign In in the top-right

  3. Use the account assigned to you

    If you were assigned the investor role, use investor@test.com / TestPass123!. For other roles, see section 4.

  4. You should land on the role-specific dashboard

    • Investor → Portfolio overview with stat cards (Total Portfolio Value, Monthly Income, Active Properties)
    • Property Owner → Owner dashboard with My Properties
    • Broker → Broker dashboard with referral and commission tabs
    • Admin → Either the operator dashboard or Django Admin at /admin/

  5. Confirm the role pill in the top-right

    The avatar dropdown shows your role (e.g. "Investor"). If it shows the wrong role, log out and back in.

Success looks like

You're on a dashboard, your name is shown in the top-right, and you don't see a "session expired" banner. If you see one, your cookies didn't get set — try a different browser or clear cookies and log in again.

9. What to look for

We need feedback in four categories. Tag your bug reports so triage is faster.

Functional bugs (blocker / major)

  • A button does nothing or 500s
  • A form submit drops your input or saves the wrong values
  • An investment / payment / mint succeeds but doesn't show up
  • Tokens don't appear in the investor portfolio after a successful payment
  • A refund is owed but doesn't get issued

Logic bugs (major)

  • A property classified as ready_property shows construction-milestone fields
  • An under-construction property tries to auto-distribute rental income
  • The KYC gate lets a non-approved investor invest
  • An installment investor sees their tokens before paying all installments

UX / cosmetic bugs (minor / cosmetic)

  • Typos, broken layouts, inconsistent fonts
  • Hover/focus states missing
  • Mobile breakage
  • Wrong currency symbol, missing decimal places

Performance bugs

  • Page takes > 5 seconds to load on a normal connection
  • Dashboard widgets are loading-spinning forever (and the network panel shows requests succeeded)
  • WebSocket reconnects repeatedly

10. Known issues — do NOT file

These are intentional limitations of the current build. Please don't file bugs for them.

BehaviourReason
Rental distributions aren't sent automatically on the configured frequency The auto-scheduler is a stub. Distributions in this build are triggered manually by owner/admin and run end-to-end correctly when triggered.
"Construction milestones" panel is empty for some properties Milestones are loaded from the construction API. Properties without milestones added yet show an empty state — that's correct behavior, not a bug.
Investor portfolio shows "0 tokens" briefly after a successful investment The on-chain mint runs asynchronously after payment confirmation. The portfolio refreshes every 30 seconds; refresh manually if impatient.
Stripe test cards work but real cards are rejected We're in Stripe test mode. This is correct — real cards must not be charged.
Some chart axes show $0–$0 The seed data doesn't have enough history yet for meaningful charts.
Password reset email doesn't arrive in local dev Local SMTP backend prints to console. Check the backend terminal output to see the reset link.
Smart-contract addresses change between deployments We redeploy as we patch. Always refer to the on-chain verification guide for current addresses.

11. Where to send bugs and questions

Your project lead set up a specific channel for bug reports. If you don't know what it is, ask them. If you're testing without a project lead, just open GitHub issues directly on the repo.

For urgent questions during testing:

  • Platform completely down or broken — ping immediately
  • I can't log in — check the password (case-sensitive) and verify the seeded account hasn't been changed
  • I want to know if X is expected behavior — check the relevant role guide first, then ask
