Ready Property Lifecycle

Walk a single ready (income-generating) property end-to-end: owner lists it, admin approves, owner tokenizes, three investors buy upfront, owner distributes rental income across three quarters, investors claim dividends.

Time: ~60 minutes
Prereqs: All four role guides
Test accounts: owner, 3 investors, admin

3. Stage 2: Admin approves

  1. Admin session B → Django Admin → Property approvals

  2. Find DIFC Office Park, approve it

4. Stage 3: Owner tokenizes

  1. Owner session A → Tokenize this property

  2. Confirm the parameters:

    • Category sent to factory as 1 (READY_PROPERTY)
    • Lockup 365 days (vs 730 for under-construction)
    • RentalIncomeDistributor IS deployed (this is a Ready property)

  3. Click Deploy. Wait for both contracts to deploy.

Expected end of stage 3

Property.status = tokenized. Two contract addresses populated: the RealEstateToken clone AND the RentalIncomeDistributor clone. BSCScan shows both deployments and a PropertyActivated event.

3.1 Verify both contracts exist

  1. Django Admin → Blockchain → Smart contracts

  2. Filter by property = DIFC Office Park

  3. You should see two rows:

    • contract_type = real_estate_token
    • contract_type = rental_distributor

5. Stage 4: Three investors buy upfront

Each investor session in parallel.

5.1 Investor A — 100 tokens ($8,000)

  1. Open DIFC Office Park

  2. Confirm visible: monthly rental income, distribution frequency, occupancy rate, expected dividend per token. NOT visible: construction progress / milestones.

  3. Click Invest. Enter 100 tokens. Click Choose Payment

    (For a Ready property the schedule step is skipped — you go straight from amount to payment.)

  4. Pay with test card. Receive 100 tokens.

5.2 Investor B — 250 tokens ($20,000)

Same flow, different investor session, different token count.

5.3 Investor C — 50 tokens ($4,000)

Same flow.

Expected end of stage 4

Property has 3 investors holding 400 tokens total ($32,000 raised of $800,000 target = 4% funded). Each investor's wallet shows the correct token balance.

6. Stage 5: Quarter 1 rental distribution

Owner session A.

  1. Owner dashboard → Revenue tab → pick DIFC Office Park

  2. Click Distribute Rental Income

  3. Form:

    • Total amount: 15000 (one quarter = 3 months × $5,000)
    • Distribution period: "Q1 2026"

  4. Review the preview:

    • Total: $15,000
    • Platform fee (2.5%): $375
    • Net distribution: $14,625
    • Per-token: $14,625 / 10,000 = $1.4625 per token
    • Eligible investors: 3 (A: 100 tokens, B: 250, C: 50)
    • Investor A receives: $146.25
    • Investor B receives: $365.63
    • Investor C receives: $73.13
    • (Note: 9,600 tokens are unclaimed — the property is only 4% sold. Those don't accrue dividends.)

  5. Click Confirm distribution

    On-chain: the RentalIncomeDistributor contract gets called with the total amount. Each investor can claim their share.

Expected end of stage 5

DistributionId 0 created on chain. RentalIncomeDistributed event emitted. All 3 investors see a "Dividend available to claim" notification. Owner sees "Last distribution: $15,000 on {date}".

7. Stage 6: Investors claim dividends

Each investor session.

  1. Investor A: Portfolio → Activity → "Dividend available" entry → Claim

    The platform calls claimRentalIncome on the distributor contract. Investor's platform wallet is credited $146.25.

  2. Investor B: same flow. Credited $365.63.

  3. Investor C: same flow. Credited $73.13.

Alternative: auto-distribute

In production, claims are usually automatic — the platform sends the dividend to the investor's wallet immediately upon distribution. In this build, claims are explicit. Both flows exist; check with your project lead which mode this test environment is in.

Owner triggers two more distributions, simulating the property running through three quarters.

  3. Q3: Owner runs once more with $15,000 for "Q3 2026" — but this time only $13,500 because Investor C decided to sell mid-quarter (see stage 8 for the partial-quarter math)

9. Stage 8: Investor exits via early-exit penalty

The lockup period for Ready properties is 365 days. Within that period, an investor who wants to exit faces an early-exit fee (default 10%). After lockup, they can exit fee-free or sell on the marketplace.

9.1 Investor C decides to exit early

  1. Investor C: Portfolio → DIFC Office Park → Exit early

  2. Confirmation dialog shows:

    • 50 tokens × $80 = $4,000 buyback at par
    • Early-exit fee (10%): -$400
    • Net to investor: $3,600
    • Tokens get burned on-chain

  3. Investor confirms. The platform:

    • Calls burnTokens(0, investor_address, 50) on the property contract
    • Credits the investor's platform wallet with $3,600
    • Marks 50 tokens as available again in property.tokens_sold

Marketplace alternative

Investors can avoid the early-exit fee by listing their tokens on the marketplace at any price. If another investor buys, the seller receives the sale proceeds minus the 2.5% platform fee — typically a better deal than the 10% early-exit penalty. See marketplace workflow.

10. What can go wrong

StageFailureExpected response
1 (list property)Owner submits with rental_income_active=true but no monthly_rental_incomeBackend rejects with validation error
3 (tokenize)RentalIncomeDistributor deployment fails after RealEstateToken succeedsProperty has token contract but no distributor; admin must intervene; rental distribution unavailable until fixed
4 (invest)Tries to over-subscribe (e.g. 11,000 tokens when 10,000 available)Validation rejects
5 (distribute)Owner enters amount = 0Validation rejects
5 (distribute)Owner enters amount > collected rent (no real-world enforcement)Allowed — owner can choose to overpay; warning shown
5 (distribute)Distribute called on an under-construction property by mistakeBackend rejects with "Only for ready properties" — the on-chain contract also has the same guard
6 (claim)Investor tries to claim twiceSecond attempt rejected; on-chain contract guards against double-claim
6 (claim)Investor has 0 tokens at distribution timeDistributor returns "Nothing to claim"
8 (early exit)Investor in lockup period tries to early-exit but property exit_disabled flag is setRefused with "Exits temporarily disabled by platform"
