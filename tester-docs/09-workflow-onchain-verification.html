On-Chain Verification

Everything that happens in the smart contracts is independently verifiable on BSCScan. This guide teaches you how to prove that your tokens were minted, that an installment really released, that a marketplace trade actually settled, and that a rental distribution went out.

Time: ~30 minutes (familiarization)
Prereqs: Completed at least one investment in Investor guide
Tool: testnet.bscscan.com

1. What "verifying on chain" means

Capimax stores critical actions in two places: the off-chain database (where it's fast and queryable) and the on-chain smart contract (where it's tamper-evident and public). The on-chain copy is the source of truth.

Verifying on chain means: instead of trusting what the platform UI shows you, you read the blockchain directly and confirm the same values. It's the test that proves the platform isn't just pretending.

Why this matters for testing

If the platform UI says "you own 25 tokens" but the chain says "you own 0 tokens", that's a serious bug. We need testers to actively check both surfaces and report discrepancies.

2.1 Per-property contracts

Each tokenized property gets its own clone of the RealEstateToken template. To find a specific property's contract:

  1. Open the property detail page on the platform

  2. Look for "Contract: 0x…" or "View on BSCScan" link

  3. OR: Django Admin → Blockchain → Smart contracts → filter by property = "{title}"

3. BSCScan basics

BSCScan is the block explorer for the BNB Smart Chain. The testnet version lives at testnet.bscscan.com.

3.1 Three ways to search

  • By address — see all activity for a wallet or contract: https://testnet.bscscan.com/address/{address}
  • By transaction hash — see one specific transaction: https://testnet.bscscan.com/tx/{tx_hash}
  • By block number — see all transactions in a block: https://testnet.bscscan.com/block/{block_number}

4. Verify a token mint

After you invest, the platform shows a transaction hash on the confirmation page. Let's verify it.

  1. Click the BSCScan link from the investment confirmation page

    OR copy the transaction hash and paste it into BSCScan's search bar

  2. You land on the transaction detail page. Verify:

    • Status: should be "Success"
    • From: the platform's deployer wallet (0x9278A6…) — the platform signs your mint, not you
    • To: the per-property contract address
    • Value: 0 BNB (mint doesn't transfer native currency)
    • Transaction Fee: a small amount of tBNB (gas)

  3. Scroll to the "Logs" section. You should see an event with topic TransferSingle

    The TransferSingle event is the ERC-1155 standard mint/transfer event. Decoded fields:

    • operator: platform deployer wallet
    • from: 0x0000000000000000000000000000000000000000 (zero address means mint)
    • to: your wallet address
    • id: 0 (each clone holds one property at tokenId 0)
    • value: the number of tokens minted

  4. If the "from" address is NOT the zero address, this wasn't a mint — it was a transfer. That's a different operation; ensure you opened the right transaction.

Mint verified

You've now independently confirmed that the platform's claim of "tokens minted" matches a real on-chain event. Anyone with the transaction hash can do this same check.

5. Verify a token balance

Mint events confirm that tokens arrived. But tokens can leave too (transfer, burn, sell). To check current balance, you call the contract directly.

  1. Open the per-property contract on BSCScan

    e.g. https://testnet.bscscan.com/address/0x32a0858993065C6343C85BC4961c3D462042792D

  2. Click the Contract tab → Read Contract

  3. Find balanceOf in the function list

    This is the ERC-1155 balance accessor. Parameters:

    • account: the wallet address whose balance you want
    • id: 0 (the propertyId inside this clone)

  4. Enter your wallet address + 0, click Query

  5. The returned value is your current balance in this property

5.1 Check the escrow balance

If you're an installment investor, some of your tokens are held in escrow on the contract itself. To see how many:

  1. Same balanceOf function

  2. Pass the CONTRACT'S OWN ADDRESS as the account, and 0 as the id

    e.g. for the contract at 0x32a0…, pass 0x32a0858993065C6343C85BC4961c3D462042792D as account.

  3. The result is the total tokens in escrow (across all installment investors)

6. Verify an installment release

When an installment is paid, the platform calls processInstallment on the contract. That call emits two events: InstallmentPaid and TokensGraduated.

  1. Find the transaction hash for the installment release

    Either from the investor's notification, or from Django Admin → Investments → Construction installment payments → the row's blockchain_tx_hash field.

  2. Open it in BSCScan

  3. Logs section should contain three events:

    EventMeaning
    TransferSingle (from contract to investor)Tokens leave escrow, land in investor wallet
    InstallmentPaidCounter incremented; emitted fields: tokenId, investor, installmentNumber
    TokensGraduatedConfirmation event: tokenId, investor, amount

  4. Read the contract state to confirm:

    • Investor's wallet balance increased
    • Contract's escrow balance decreased by the same amount
    • investors(tokenId=0, investor_address).installmentsPaid equals the new paid count

7. Verify a marketplace trade

A marketplace trade settlement results in a TransferSingle event where tokens move from seller to buyer (not from zero address).

  1. Find the transaction from the platform's trade record

    Marketplace → Trade transactions → the row's transaction_hash

  2. Open in BSCScan, find the TransferSingle event:

    • operator: marketplace contract or matching engine signer
    • from: seller wallet
    • to: buyer wallet
    • id: property tokenId (0 inside the clone)
    • value: tokens traded

  3. Verify the balances changed accordingly — seller's decreased, buyer's increased, by the same amount

8. Verify a rental distribution

Rental distributions happen on the per-property RentalIncomeDistributor contract (separate from the token contract).

  1. Find the distribution's transaction hash

    Owner dashboard → Revenue → Distribution history. Or Django Admin → Blockchain → Rental distribution rows.

  2. Open in BSCScan

  3. Logs should contain a RentalIncomeDistributed event:

    • tokenId: 0
    • distributionId: monotonic counter (first distribution = 0)
    • totalAmount: amount distributed (in wei)

  4. If individual investor claims have happened, each one emits a RentalIncomeClaimed event:

    • tokenId: 0
    • distributionId: which distribution
    • investor: claimer's wallet
    • amount: their share

  5. To check your eligibility for a distribution, read rentalDistributions(tokenId=0, distributionId) on the distributor contract. It returns total amount, eligible tokens at distribution time, distribution date.

9. Reading on-chain state directly

The "Read Contract" tab on any contract page exposes all the public view functions. Useful queries:

FunctionReturnsUse
balanceOf(account, id) Token balance for a single id Check ownership
properties(tokenId) Struct: totalSupply, currentSupply, category, status, lockupPeriod, earlyExitFeeRate, rentalYieldRate, propertyManager, propertyURI, tokenPrice, createdAt, completionDate, rentalIncomeActive Inspect any property's core fields
investors(tokenId, address) Struct: tokenBalance, totalInvested, firstInvestmentTime, lockupEndTime, hasEarlyExit, installmentsPaid, totalInstallments Per-investor record
rentalDistributions(tokenId, distributionId) Distribution record Past distributions
totalSupply(id) Total tokens in circulation for this property Sanity check
uri(id) Metadata URI for the property Inspect property metadata

9.1 Example: Confirm a property is ACTIVE

  1. Open the per-property contract → Read Contract

  2. Call properties(0)

  3. Look at the status field

    PropertyStatus enum values: 0=DRAFT, 1=ACTIVE, 2=PAUSED, 3=COMPLETED, 4=CANCELLED

    For an investable property, expect 1 (ACTIVE).

11. When BSCScan and the platform disagree

Source of truth: the chain. If the platform UI shows different balances or different transactions than BSCScan, the platform's off-chain database is out of sync.

11.1 Symptoms to file as bugs

  • Platform says you own N tokens; chain says you own M (M != N)
  • Platform shows a transaction as completed; chain shows it reverted
  • Platform shows escrow balance > 0; chain shows the contract holds 0 tokens
  • Dividend amount in platform doesn't match the chain's per-token math

11.2 What to include in your report

  • BSCScan transaction or address link
  • Screenshot of the platform UI showing the disagreement
  • Your wallet address
  • The exact contract address you queried on chain
  • Result of the balanceOf call (or whatever read function you used)
  • Result of the platform's API call (open browser dev tools → Network → copy response body)

Treat chain≠platform divergence as a blocker

This is the most serious class of bug. It usually means the platform's reconciliation jobs failed or never ran. Ping your project lead immediately — don't wait for the bug-tracker triage cycle.
