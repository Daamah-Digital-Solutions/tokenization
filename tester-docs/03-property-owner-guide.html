Property Owner Guide

Everything a property owner does on the platform: account setup, SPV onboarding, listing both ready and under-construction properties, managing tokenization, adding construction milestones, distributing rental income, and monitoring investors.

2. SPV setup

Each property is held by a Special Purpose Vehicle (legal entity). Real platforms require this for regulatory reasons. In our test environment, the SPV fields are optional until the property is approved — you can fill them later.

2.1 Where to set SPV details

  1. My Properties → pick a property → Edit

  2. Open the "SPV (Special Purpose Vehicle)" section

    You'll see:

    • SPV company name
    • SPV registration number
    • SPV bank account number
    • SPV bank name
    • SPV establishment date

  3. Fill the fields with sensible test data (any string is fine)

  4. Save

    The property page now shows "SPV: {company name}" in the metadata bar.

3. Listing a Ready property

Ready properties are income-generating (already built, rented out). Investors buy tokens and receive a share of the rental income.

  1. From the dashboard, click Add New Property

  2. Step 1: Basic Information

    • Title: e.g. "Downtown Apartment Complex"
    • Description: a paragraph of plain text
    • Property type: Residential / Commercial / Industrial / Mixed-use / Land
    • Property category: choose Ready Property

  3. Step 2: Financial Details

    • Total value (e.g. 500000)
    • Token price (e.g. 100)
    • Total tokens (auto-calculates from value/price; you can override)
    • Expected return (% annual)
    • Rental yield (% annual)
    • Minimum investment (e.g. 100)

  4. Step 3: Property Details

    • Address, city, state, country, postcode
    • Property size (sqm)
    • Year built
    • Latitude / longitude (auto-populates from address if available)

  5. Step 4: Rental income (Ready-property specific)

    • Monthly rental income (e.g. 4000)
    • Rental distribution frequency: Monthly / Quarterly / Semi-annual / Annual
    • Occupancy rate (%)
    • Rental income active (toggle ON)

  6. Step 5: Images

    Upload 1+ image files. Drag & drop or click to select. Mark one as primary.

  7. Step 6: Documents (optional)

    Upload PDF / DOCX files. Tag each with a document_type (lease, deed, valuation, etc.)

  8. Click Submit for Approval

    Status moves to Pending approval. The property won't appear in the public listings until admin approves it.

What should NOT appear for Ready properties

Construction completion date, construction progress, installment toggle. If they show up on the Ready property form, that's a bug.

4. Listing an Under-Construction property

Under-construction properties offer optional installment payments and show construction progress. Investors lock in their stake during construction and graduate to full ownership as construction completes.

  1. Click Add New Property

  2. Step 1: Basic Information

    Same as Ready, but set Property category to Under Construction.

  3. Step 2: Financial Details

    Same fields. Set Expected return based on completion value.

  4. Step 3: Property Details

    Same fields, plus:

    • Expected completion date (required)
    • Construction progress (%): start at 0
    • Construction phase (Foundation, Framing, Interior, Finishing …)

  5. Step 4: Installments (Under-construction specific)

    • Supports installments — toggle ON to enable installment investing
    • Installment period (months) — e.g. 12
    • (Optional) Down payment percentage

    If you keep "Supports installments" OFF, investors can only pay upfront.

  6. Continue with Images and Documents as in the Ready flow

  7. Click Submit for Approval

What should NOT appear for Under-Construction

Monthly rental income, rental distribution frequency, occupancy rate. The "Rental income active" toggle should be hidden or default off. Under-construction properties don't generate rental until completion.

5. The approval workflow

After submission, your property is in pending_approval state. The admin reviews it via Django Admin (see Admin guide). One of three outcomes:

  • Approved — status flips to approved. You can now tokenize.
  • Rejected — status flips to rejected. Notes from admin appear in the approval card. You can edit and resubmit.
  • Under review — admin needs more info. They'll comment; you respond.

5.1 Tracking your approval

  1. My Properties → your property → the approval panel at the top

    Shows: current status, who's reviewing, when submitted, comments thread

  2. Approved properties show "Tokenize this property" button

6. Tokenization — deploying smart contracts

Tokenization deploys the smart contracts that represent ownership of this property on the blockchain. Once tokenized, the property accepts investments and tokens get minted to investor wallets.

  1. On an approved property, click Tokenize this property

  2. Confirmation dialog shows the parameters:

    • Total tokens (from your financial details)
    • Token price
    • Lockup period (default 365 days for ready, 730 for construction)
    • Early exit fee rate (default 10%)
    • Multi-sig owners (you + platform treasury, by default)
    • Estimated gas cost in tBNB

  3. Click Deploy

    A progress indicator runs through three stages: deploying token contract, deploying distributor contract (Ready only), activating property.

  4. On success:

    • Property status flips to tokenized
    • The property's smart-contract address is recorded and shown on the property card
    • "View on BSCScan" button appears
    • The property becomes visible in the investor marketplace

Deployment failures

If deployment fails (out of gas, network error), the property stays in approved state and you can retry. The retry should be idempotent — you should never end up with two contracts for the same property. If you do, file a bug.

6.1 Verify your contracts on chain

After deployment, open the BSCScan link. You should see:

  • Contract creation transaction (your tokenization tx)
  • "Property activated" event (the platform calls activateProperty right after deploy)
  • Contract source — verified RealEstateToken

See on-chain verification for the complete walkthrough.

7. Watching investors come in

7.1 Investor list

  1. Side nav → Investors

  2. You see:

    • Top Investors table: name, total invested, properties count, join date
    • Investor Distribution: Retail / Institutional / High Net Worth segments
    • Investment Metrics: Average Investment, Total Capital Raised, Retention, New Investors (30d)

  3. (Privacy) Investor email addresses are NOT shown to property owners

    You see names only, never emails. If you can see an investor's email, that's a serious privacy bug — report immediately.

7.2 Investment activity

  1. Overview → Recent activity shows every new investment in your portfolio

  2. Each row links to the transaction on chain

8. Construction milestones

For under-construction properties, you can add milestones that investors see on the property detail page.

  1. Open an under-construction property → the Construction Progress section

  2. Click Add Milestone

  3. Fill the form:

    • Title: e.g. "Foundation complete"
    • Description
    • Category: Site preparation / Foundation / Framing / Interior / Finishing / Inspection / Other
    • Target date
    • Completion date (leave blank until done)
    • Progress %

  4. Save. The milestone appears in the investor view immediately.

  5. Add a milestone update (sub-event) and attach an image

    Optional but useful. Investors see "Update: Foundation poured on May 12" with an attached photo.

  6. Mark the milestone complete

    Edit it → set status to "Completed" → enter actual completion date. The overall construction progress bar updates.

9. Distributing rental income

For ready properties only. When you've collected rent, distribute it to token holders.

  1. Open a tokenized ready property → the Revenue tab

  2. Click Distribute Rental Income

  3. Enter:

    • Total amount (e.g. 4000)
    • Distribution period (e.g. "May 2026" or a date range)

  4. The platform calculates:

    • Platform fee (2.5%)
    • Net amount to distribute
    • Per-token payout (net / total tokens)
    • List of eligible investors and how much each receives

  5. Click Confirm distribution

    On-chain: the RentalIncomeDistributor contract is called with the total amount; each token holder can claim their share. You see a "View on chain" link.

  6. Verify in your dashboard

    Revenue tab → "Last distribution: ${amount} on {date}". Eligible-investor count updated.

Auto-distribution is stubbed

In the current build, the celery cron that auto-triggers distributions on the configured frequency is a stub. Distributions must be triggered manually from this UI for now. Don't file as a bug if you don't see automated distributions appearing.

10. Property documents

  1. Side nav → Documents or open a property → Documents tab

  2. Upload a new document

    • File (PDF, DOCX, JPG, PNG)
    • Name
    • Document type: Lease agreement / Deed / Valuation / Insurance / Permit / Photo / Other
    • Description

  3. Save. The document appears in your list and on the property's public detail page.

  4. Try deleting it — should ask for confirmation, then remove

  5. Try uploading a 50MB file — expect a clear "too large" message

11. Reports & analytics

11.1 Revenue tab

Total RevenueSum of all rental income + new investments YTD
Pending DistributionsAmount queued but not yet distributed
Next DistributionDate of upcoming scheduled distribution (or "TBD")
Distribution RateCurrent month revenue

11.2 Per-property performance

Tokenization tab → Performance Comparison. Each property row shows:

  • ROI
  • Monthly revenue
  • Occupancy rate (ready) or construction progress (under-construction)
  • Token price change since tokenization

11.3 Generate a report

  1. My Properties → pick a property → Generate Report

  2. Pick a report type:

    • Financial — revenue, fees, net
    • Performance — ROI, occupancy, milestones
    • Investor — list of holders + amounts (privacy-redacted)

  3. Click Generate. The platform returns a download link.

12. Error paths to test

ScenarioExpected response
Submit property with missing required fields Inline errors on each missing field
Submit Ready property without monthly_rental_income Validation error: "Monthly rental income required when rental_income_active is on"
Submit Under-Construction without expected_completion_date Validation error: "Expected completion date is required"
Try to tokenize a property in pending approval status Button disabled, tooltip explains
Try to tokenize without SPV fields filled Should warn but not block (test environment is lenient)
Try to distribute rental on an Under-Construction property Distribute button hidden OR rejected with "Not applicable for this property type"
Try to add milestones to a Ready property Milestone UI hidden OR refused
Distribute more than property's current month rental Should warn but allow (owner's call — bonus distribution)
Edit a property after it's been tokenized Financial fields locked (changing them post-tokenization would break the contract); descriptive fields still editable
Try to delete a property with investors Refused with "Property has active investments"
View another owner's properties via URL guessing 403 or empty results
