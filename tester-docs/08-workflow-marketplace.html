Marketplace Trading

The secondary market lets investors trade tokens with each other without going through the property owner. This guide covers listing, order placement, matching engine settlement, escrow, fee calculations, and edge cases.

Time: ~45 minutes
Prereqs: Investor guide, completed an investment in any property
Test accounts: two investor accounts holding tokens

1. Marketplace concepts

TermMeaning
MarketListingAn investor's intent to buy or sell. Has type (BUY or SELL), price per token, total tokens, status
TradeOrderA counter-party order against a listing. Type LIMIT or MARKET
TradeTransactionA successful match. Tokens move from seller to buyer; funds move buyer to seller
EscrowAccountTemporarily holds buyer's funds + seller's tokens until both sides confirm. 24-hour default timeout
TradingPairA pair of properties that can be traded against each other (token/token swaps). For most testing you'll use property/USD
Matching engineBackend service that matches buy/sell orders by price priority + time priority

2. Fee structure

Volume tier (30d)Maker rateTaker rate
Base (0)2.0%2.5%
$10k+1.5%2.0%
$50k+1.0%1.5%
$100k+0.5%1.0%
$500k+0.0%0.5%
  • Maker = the side that posted the resting order. Pays lower fee because they provided liquidity.
  • Taker = the side that matched against an existing order. Pays higher fee.
  • For testing, you'll usually be at base tier (2%/2.5%).

3. Prerequisites & setup

Before this workflow, you need:

  • A tokenized property (e.g. DIFC Office Park from the Ready property workflow)
  • At least two investor accounts holding tokens in that property
  • Each investor has a valid linked wallet

For the steps below, assume Investor A holds 100 tokens of DIFC Office Park at $80 each. Investor B has no tokens yet but wants to buy. Both have completed KYC.

4. Stage 1: Investor A creates a listing

Browser session A — investor@test.com.

  1. Portfolio → DIFC Office Park → Sell on marketplace

    OR — Marketplace → Create Listing

  2. Listing form:

    • Property: DIFC Office Park (auto-filled if reached from holding)
    • Listing type: Sell
    • Tokens offered: 40 (Investor A keeps 60)
    • Price per token: 82 (slightly above purchase price)
    • Minimum order size: 1 (default; can be raised)
    • Expires at: 14 days from now
    • Allow partial fills: ON (default)

  3. Review the listing preview

    • 40 tokens × $82 = $3,280 maximum sale
    • Maker fee at base tier (2%): -$65.60
    • You receive: $3,214.40 (if fully sold)

  4. Click Create Listing

    On-chain: Investor A's 40 tokens are escrowed on the marketplace contract. Investor A's wallet balance drops from 100 to 60 for this property. Escrow holds 40.

Expected end of stage 1

MarketListing created with status active. 40 tokens are locked. Listing visible on the marketplace page for everyone. Investor A's portfolio shows 60 active + 40 listed.

5. Stage 2: Investor B places a buy order

Browser session B — investor2@test.com.

  1. Marketplace → find DIFC Office Park → click on the row

  2. Order book view appears:

    • Asks (sell orders): Investor A's listing at $82 for 40 tokens
    • Bids (buy orders): empty so far
    • Spread: N/A (no bids yet)
    • Last trade price: $80 (the initial mint price)

  3. Click Buy

  4. Order form:

    • Order type: Market (takes the best available ask) OR Limit
    • Tokens to buy: 25
    • If Limit: price per token (set to 82 to match)
    • Source of funds: platform wallet OR top-up via card

    Use Market type for this test — should match Investor A's $82 ask immediately.

  5. Review preview:

    • 25 tokens × $82 = $2,050
    • Taker fee at base tier (2.5%): $51.25
    • Total you pay: $2,101.25

  6. Click Place Order

Expected end of stage 2

TradeOrder created. Funds escrowed. The matching engine immediately sees this order, matches it against Investor A's listing, and begins settlement (covered next).

6. Stage 3: Matching engine settles

The matching engine runs synchronously when an order is placed. It pairs the highest bid with the lowest ask. Settlement happens in two phases.

6.1 Phase 1 — create TradeTransaction

The engine creates a TradeTransaction with:

  • buyer = Investor B
  • seller = Investor A
  • property_traded = DIFC Office Park
  • tokens_traded = 25
  • price_per_token = $82
  • total_amount = $2,050
  • status = PROCESSING → IN_ESCROW

6.2 Phase 2 — escrow holds the trade

An EscrowAccount is created:

  • transaction = the TradeTransaction
  • amount_held = $2,101.25 (Investor B's payment + their fee)
  • tokens_held = 25 (out of Investor A's 40 listed)
  • timeout_at = 24 hours from now
  • status = HOLDING

6.3 Phase 3 — auto-release (default)

In the standard flow, escrow auto-releases as soon as the on-chain transfer of tokens succeeds. The token transfer is initiated immediately:

  1. Marketplace contract calls safeTransferFrom(seller, buyer, propertyId, 25, "") on the property's token contract
  2. Tokens move from Investor A's wallet to Investor B's wallet
  3. Marketplace contract emits TradeSettled
  4. Backend service marks Escrow as RELEASED, TradeTransaction as COMPLETED
  5. Buyer's escrowed funds are released to seller (net of fees)
  6. Platform fee is taken out

Expected end of stage 3

TradeTransaction.status = COMPLETED. Escrow.status = RELEASED. Investor B's wallet now holds 25 tokens. Investor A's wallet still holds 60 (plus 15 in escrow because their listing was for 40 and only 25 sold — we cover partial fills below).

7. Stage 4: Escrow lifecycle

In the happy path above, escrow opens and closes within seconds. The escrow state machine is more interesting on failure paths.

7.1 Escrow states

StateMeaning
HOLDINGFunds + tokens locked; waiting for on-chain transfer
RELEASEDTransfer succeeded; tokens delivered, funds settled
REFUNDEDBuyer got their funds back; tokens returned to seller
TIMED_OUT24 hours passed without resolution; auto-refund queued
DISPUTEDOperator-flagged; manual review required

7.2 Test the timeout path

To simulate a stuck escrow, an admin can force one into HOLDING state via Django Admin and let it sit. After 24 hours, the auto-refund task runs and flips to TIMED_OUT → REFUNDED.

  1. Admin creates a TradeTransaction manually (or finds one stuck in IN_ESCROW)

  2. Verify escrow row exists with timeout_at < now

  3. Either wait for the cron, OR manually trigger the auto-refund task from Django shell

  4. Verify escrow.status = REFUNDED, transaction.status = FAILED

  5. Verify buyer's funds returned to their wallet, seller's tokens unlocked

  2. Match settles. Listing.tokens_remaining = 0. Status flips to FILLED.

  3. Owner-side analytics increment cumulative trade volume

9.3 Test minimum-order-size enforcement

  1. Create a new listing with minimum_order_size = 10

  2. Try to place a buy order for 5 tokens against it

  3. Expected: order rejected with "Below minimum order size"

10. Expired listings

  1. Create a listing with expires_at = 1 hour from now

  2. Wait (or fast-forward via admin) until past expiry

  3. Confirm listing.status = EXPIRED automatically (background task runs every few minutes)

  4. Escrowed tokens return to seller's wallet automatically

11. Cancelling a listing or order

11.1 Cancel an active listing

  1. Marketplace → My Listings → Cancel a listing in ACTIVE or PARTIALLY_FILLED state

  2. Confirmation dialog explains: "Your remaining 15 tokens will return to your wallet"

  3. Confirm. Listing.status = CANCELLED. Tokens unescrow.

11.2 Cancel a pending buy order

  1. If your order is in PENDING (no match yet), you can cancel

  2. Order.status = CANCELLED. Any escrowed funds return.

  3. If your order is already FILLED or PARTIALLY_FILLED, cancel only removes the unfilled portion

12. Operator interventions

Admin can intervene in marketplace state. See Admin Guide · Marketplace moderation for full instructions. Highlights:

  • Cancel suspicious listings — bulk cancel from list view
  • Force release escrow — manual settlement when chain state is good but engine got stuck
  • Force refund escrow — manual cancel when something went wrong on-chain
  • Mark trade as FAILED — terminal failure marker (use after on-chain investigation)
  • Pause the marketplace — emergency factory-level pause stops all new trades
