Investor Guide

A complete walkthrough of the investor journey: signing up, completing KYC, browsing properties, investing in both upfront and installment modes, viewing your portfolio, trading on the marketplace, and withdrawing.

Time: ~45 minutes
Prereqs: Tester Onboarding
Test account: investor@test.com

1. Sign up & account verification

Pre-seeded accounts already exist. This section covers the brand-new sign-up flow — only test it once per round (use any email you control, since the email verification step will need to be completed).

  1. Open the homepage and click Create Account

  2. Fill the form

    • Email — any address you can receive mail at
    • Password — minimum 8 chars, must include letter + number + symbol
    • First and last name
    • Role selector — choose Investor

  3. Submit. You'll see a confirmation screen telling you to check your email.

    Local dev only: the email is printed to the backend console rather than sent. Look for "Verification link" in the terminal where Django is running.

    Staging: the email arrives at the address you entered.

  4. Click the verification link in the email

    You land on a confirmation page. From here, sign in normally with the email + password you just set.

Sign-up does not automatically log you in

This is intentional. After verifying your email you must explicitly log in. If you find yourself auto-logged-in, that's a bug.

2. KYC verification

Before you can invest, you must complete KYC (Know Your Customer). All seeded test investors have status Approved; new sign-ups start as Not started.

2.1 Start the KYC wizard

  1. From the investor dashboard, find the "Complete your verification" banner OR open Settings → Identity Verification

  2. Click Start verification

    You'll see a multi-step wizard.

2.2 Walk through each KYC step

StepWhat to enterExpected outcome
Personal info Full legal name, date of birth, nationality, phone Saves and advances
Address Residential address, city, postcode, country Saves and advances
ID document Upload a passport or driver's license image (use any test image — even a colored rectangle) File uploads, preview shows, advances
Selfie / liveness Upload any selfie image, OR skip if the wizard offers it Submits and shows "Under review" state
Source of funds (optional) Pick an option, enter any amount Saves
Submit for review Click Submit Status flips from Not started to Pending review

Approval workflow

In production, an external provider (Jumio) reviews the submission. In the test environment, an admin reviews and approves it via Django Admin — see the Admin guide. Once approved, you'll see "Verified" next to your name.

2.3 KYC status states

not_startedHasn't begun. Cannot invest.
in_progressStarted but didn't submit. Cannot invest.
pendingSubmitted, waiting for admin. Cannot invest.
approvedCleared. Can invest.
rejectedFailed review. Cannot invest until reapproved.

2.4 Things to test in the KYC flow

  • Field validation — submit with empty required fields, expect inline errors
  • File upload with very large files (>10MB should fail gracefully)
  • File upload with non-image files (should refuse)
  • Resume the wizard after closing it mid-step (your progress should persist)
  • Try to invest while status is pending — you should be blocked with a clear message

3. Linking a wallet

Investors need a blockchain wallet address so tokens can be minted to them. The seeded investor@test.com already has a wallet linked. New accounts must link one before investing.

  1. Go to Settings → Wallet

  2. Click Connect wallet

    If MetaMask is installed and unlocked, it pops a connection request. Approve it.

  3. Confirm the chosen address

    The wallet panel shows your address (e.g. 0xabc…def). This is what tokens will mint to.

  4. Switch your wallet to BNB Smart Chain Testnet

    If you're on the wrong network, the platform shows a "Switch network" prompt.

Mainnet vs testnet

If your MetaMask is on Ethereum Mainnet or Polygon Mainnet, the platform should refuse to do any blockchain operations. If it tries, that's a serious bug — report immediately.

4. Browsing properties

4.1 Properties list

  1. Click Properties in the top nav

    You see a grid of property cards. Each card shows: photo, title, city, type, funding bar, expected return.

  2. Use the filters

    • Property type (Residential / Commercial / Industrial / Mixed-use / Land)
    • Property category (Ready / Under construction)
    • Country / city
    • Price range
    • Minimum investment

  3. Use the search bar

    Title and description are searchable.

  4. Toggle map view (if available)

    Pin clusters group nearby properties. Click a pin to jump to that property.

4.2 Property detail page

Click any card to open the detail page. You'll see:

  • Header — title, location, type, status
  • Photos — carousel with property images
  • Investment summary — token price, total tokens, available tokens, funding progress, expected return
  • About — description + key facts
  • Documents — SPV documents, legal disclosures
  • For Ready properties: Monthly rental income card, dividend distribution schedule
  • For Under-construction properties: Construction progress bar, expected completion date, milestone list (if owner has added them)
  • Invest button — primary CTA, opens the investment flow

What should differ by category

A ready property must NOT show construction progress or milestones. An under-construction property must NOT show monthly rental income or dividend schedule. If you see the wrong fields, file a bug.

5. Investing — upfront payment

This is the standard flow. Works for both property types but is the only option for ready properties.

  1. On any property detail page, click Invest

    A multi-step modal opens.

  2. Step 1: Select Tokens

    Move the slider or type a number. The total cost updates live (tokens × token price). The amount must be ≥ minimum investment and ≤ available tokens.

  3. For ready properties: click Choose Payment

    For under-construction properties with installments enabled, you instead see a Payment Schedule step — covered in section 6. Pick "Pay upfront" to follow this flow.

  4. Step 2: Payment Method

    Select credit card, bank transfer, or crypto. For this test use credit card.

  5. Click Confirm & Pay

    If you have no saved cards, a Stripe Elements form appears. Enter 4242 4242 4242 4242, any future expiry (e.g. 12/30), any 3-digit CVC (e.g. 123), any postcode.

  6. Step 3: Processing

    The platform creates a payment intent, charges the test card, marks payment confirmed, dispatches the mint task. Spinner shows live status.

  7. Step 4: Confirmation

    You see a success card with the investment summary, the property name, the token count, and a "View on chain" link to BSCScan. Click it — you should see the mint transaction.

What success looks like

Investment ID returned, status = completed, transaction hash present, BSCScan link works, tokens appear in your portfolio within ~30 seconds.

5.1 Failure paths

SetupExpected result
Use card 4000 0000 0000 9995 (insufficient funds) Payment fails. Inline error in the dialog. No investment row created. No mint attempted.
Cancel mid-flow (close the dialog) A "Cancel investment?" confirmation appears. Choose cancel, return to property page. No charge.
Try to invest more than available tokens Inline validation blocks the input. Cannot proceed.
Try to invest below minimum Inline validation blocks. Cannot proceed.
Investor account has KYC = pending The invest button is disabled, or the dialog refuses with a clear "complete KYC first" message.
Property has requires_accredited_investor = true and investor isn't accredited Refused with 403 "This property is restricted to accredited investors".

6. Investing — installment plan

Only available on under-construction properties whose owner enabled installments. The seeded Tower Build (Installment Demo) property is configured this way.

  1. Open the Tower Build property detail page

    You should see "Under Construction" badge, completion date, and "Installments available" indicator.

  2. Click Invest

  3. Step 1: Select Tokens

    Pick a token count. Click Choose Schedule (the button label changes for installment-eligible properties).

  4. Step 2: Payment Schedule

    This step ONLY appears for installment-eligible properties. You see two cards:

    • Pay upfront — single payment. Tokens mint immediately to your wallet.
    • Pay in installments — expandable, lets you pick 3 / 6 / 12 / N installments. Each payment installs a portion of the tokens to your wallet.

    Choose Pay in installments and pick 4.

  5. Click Choose Payment

  6. Step 3: Payment Method

    Pick credit card. The recurring-charge consent banner appears — check it.

  7. Click Confirm & Pay

    Enter test card. The first installment is charged immediately.

  8. Step 4: Processing

    Behind the scenes: investment created, first payment captured, on-chain mint with isInstallment=true, total tokens go into escrow on the contract, first installment's portion of tokens released to your wallet.

  9. Step 5: Confirmation

    You see "Installment 1 of 4 paid". Your wallet holds 1/4 of total tokens. Remaining tokens sit in escrow.

6.1 Verifying installment escrow on chain

Open the BSCScan link from the confirmation page. The transaction type is mintTokens. The "to" address is the per-property contract (because tokens go to escrow). Then a second transaction, processInstallment, transfers your first installment's share to your wallet.

See on-chain verification for the full step-by-step.

6.2 Subsequent installments

Each subsequent installment runs automatically on the schedule. For testing purposes, your project lead or admin can manually trigger installments from the admin panel so you don't wait a month.

  1. An installment payment fires — charges your card again, triggers another processInstallment on chain

  2. Check Portfolio → "Tower Build" — your token count grew by 1/4

  3. Check the timeline panel on the property detail page — payments-made counter increased

  4. After the final installment: all tokens are in your wallet, escrow = 0, status flips to "Installments complete"

Failed installment

If a recurring charge fails (test by switching your saved card to 4000 0000 0000 9995), the platform should retry per the scheduled retry policy. After max retries it marks the installment as failed. Already-released tokens are NOT clawed back — the investor keeps what they've paid for.

7. Your portfolio

Click Portfolio (or "My Portfolio") in the side nav.

7.1 What you should see

SectionContents
Stat cards (top) Total Portfolio Value, Monthly Income, Active Properties, Total Invested
Recent activity Latest investments, mints, payments, dividends
Holdings list One row per property you've invested in. Token count, current value, ROI, last activity
Performance chart Portfolio value over time (placeholder data is fine during early testing)
Allocation pie chart Property-type breakdown (Residential %, Commercial %, etc.)

7.2 Drill into a holding

Click any row. You should see:

  • The property's headline numbers
  • Your tokens / current value / total invested
  • For ready: dividend history
  • For under-construction: installment schedule (paid / upcoming) + construction progress
  • Buttons: "Sell on marketplace" / "Withdraw" (where applicable)

8. Receiving rental income

Only applies to ready properties. When the owner or admin triggers a rental distribution, every token holder receives a proportional payout.

  1. Wait for (or ask admin to trigger) a distribution on a property you hold

  2. You receive a notification — bell icon shows a red dot

  3. Open Portfolio → Activity

    You see a "Dividend received" entry with amount, property, date, and a "View transaction" link

  4. Open the property holding

    The "Total dividends" counter increased. The distribution shows in the dividend history table.

  5. Check Wallet (if you have a wallet balance view)

    The dividend amount is credited to your platform wallet (or the on-chain payable contract, depending on the distribution mechanism).

9. Selling tokens on the marketplace

Full marketplace flow is covered in Workflow 8. The short version from an investor's POV:

  1. Portfolio → pick a holding → Sell on marketplace

  2. Listing dialog: how many tokens, price per token, expiry date

  3. Submit — listing status becomes Active. Your tokens are locked in escrow on the contract for the duration of the listing.

  4. If another investor buys: matching engine settles, escrow releases buyer's tokens, your platform wallet is credited with the proceeds (minus 2.5% platform fee).

  5. Notification appears: "Your listing sold"

10. Withdrawing funds

When you have a platform wallet balance (from dividends, marketplace sales, or future support for fiat top-ups), you can withdraw it.

  1. Settings → Wallet → Withdraw

  2. Pick a destination (bank, crypto, etc.) and amount

  3. Submit. Status becomes Pending review

    Admin reviews and approves in Django Admin — see the Admin guide.

  4. Once approved, the withdrawal status becomes Processed. Funds leave the platform balance.

The bell icon in the top nav shows unread notifications. They're delivered via WebSocket in near-real-time.

Installment due in 3 days"Upcoming payment in 3 days"
Dividend received"Dividend of ${amount} received"
Marketplace listing sold"Your listing sold"
Marketplace buy order filled"Your buy order filled"

WebSocket health

A green dot near the bell indicates a live WebSocket connection. If it's grey or red, notifications may be delayed. The connection should auto-reconnect within ~5 seconds; if it doesn't, that's a bug.
