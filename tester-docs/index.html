Capimax — Real Estate Tokenization Platform

Tester Documentation

Everything you need to test Capimax end-to-end across all roles and workflows. Each guide is a self-contained operational manual — start with Tester Onboarding, then pick the role or workflow you've been asked to exercise.

Version: 1.0
Status: Internal beta
Network: BSC Testnet · Stripe Test Mode

Read this first

Capimax is currently in testnet/test-mode. All money movements use Stripe test cards; all token mints land on BSC Testnet. No real funds are at risk and no real-world assets are conveyed by test tokens. Tester Onboarding explains the environment in detail — please read it before you start.

How this documentation is organized

Each guide is a stand-alone HTML page with a step-by-step operational walkthrough. The guides are grouped into two sets:

Role guides

One per platform role. Each guide covers everything that role can do — account creation, the role's dashboard, the actions they're expected to perform, what they should and should not be able to see.

GuideAudienceTime to complete
Investor Anyone who's signing up to buy property tokens ~45 minutes
Property Owner Anyone listing a property and managing investors ~60 minutes
Broker Anyone bringing investors onto the platform ~30 minutes
Admin Platform operators using Django Admin ~60 minutes

Workflow guides

Multi-role end-to-end scenarios. These follow a single property or trade across every role that touches it.

GuideWhat you exercise
Under-Construction Lifecycle List a construction property → tokenize → investor pays in installments → tokens release as installments are paid → construction milestones → completion
Ready Property Lifecycle List an income-generating property → tokenize → investor buys upfront → rental distribution → investor receives dividends
Marketplace Trading List tokens for sale → another investor places a buy order → matching engine settles → escrow → ownership transfer
On-Chain Verification How to verify your token mints, transfers and balances on BSCScan, and where to find the deployed contract addresses

What's in scope vs out of scope

In scope for this testing round

  • Investor sign-up, KYC, browse, invest, portfolio
  • Property owner property creation, both ready and under-construction
  • Stripe payments (test cards only)
  • On-chain token mint, on-chain balance, on-chain installment release
  • Construction milestone tracking
  • Rental distribution (manually triggered by admin or owner)
  • Marketplace listings, buy orders, matching engine, escrow
  • Refund pipeline on terminal mint failure
  • Django Admin moderation flows
  • WebSocket notifications

Known limitations — do not file as bugs

  • Auto-scheduled rental distribution is a stub. Distributions in this build must be triggered manually. The button in the owner dashboard is functional; the daily celery cron is not.
  • Email delivery in localhost mode prints to the server console instead of sending. In staging the configured SMTP is used.
  • Smart-contract addresses on BSC Testnet may change between deployment rounds. The on-chain verification guide always lists the current addresses.
  • Investors must have a wallet address linked before tokens can be minted. In this round the linking is done through the wallet settings panel using a regular web3 wallet (e.g. MetaMask configured for BSC Testnet).
  • Token transfers between investors via the marketplace work, but the secondary market UI is still being polished. Buy and sell orders are fully functional; some chart components show placeholder data.
